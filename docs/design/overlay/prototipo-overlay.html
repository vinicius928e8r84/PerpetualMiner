Netflix · YouTube · Kinopoisk · HBO Max · Prime (seletor direto)funcionaO texto é lido de um elemento do DOM (.player-timedtext-text-container, .ytp-caption-segment, [data-tid=Subtitles], seletores caption/subtitle, .atvwebplayersdk-captions-text). Achou o texto = achou o elemento = tem retângulo. O grifo usa Range.getClientRects() por palavra.

Tela cheia · player em iframefuncionaO overlay vive dentro do container do player (igual ao botão hoje) e o manifest já injeta com all_frames: true.

        
Legenda trocou antes do feedback aparecer (Auto Miner espera 650 ms + resposta)reservaA linha só existe enquanto o mesmo texto está na tela; se já trocou, cai na pílula. Teste com ▶ Player tocando.

        
Fallback heurístico (Prime por varredura, minerarLegendaVisual)reserva / riscoAcha um elemento, mas pode ser o errado → linha no lugar errado. Construção: só desenhar a linha quando o texto do elemento bate com o que foi salvo.

        
Seleção dentro de <input>/<textarea>, visualizador de PDF, Google Docs (canvas)reservaSem retângulo de texto acessível → pílula.

        
Legenda desenhada como imagem/canvasnem hojeO miner já não consegue ler esse texto; não é um caso novo.

      
    

    
Resumo: a linha é 100% viável em todo lugar onde a mineração já funciona, mas não é 100% garantida no momento do feedback. Por isso toda mistura tem a pílula como reserva. Na construção, o scraping precisa devolver {texto, elemento} em vez de só o texto: muda o retorno, não o comportamento. Verificado lendo o código, não ao vivo nos sites.
