# The opener knows three things, and is registered where it was seen to work

The opener is a small script the Conexão writes, with the path of the Anki and the profile, and registers as a Native Messaging host. It knows only three messages: `conferir` (is the Anki where it was noted), `abrir` and `consertar`; anything else is `{"erro": "acao_desconhecida"}`. Nothing stays running in the background: the browser runs it, it answers once and leaves. It is rewritten at every `profile_did_open` and at every choice of profile, with the marked profile, and the write is whole (written beside and swapped), so the browser never runs half a script.

It is registered only where it has been seen to work. On the Mac, in the Chrome hosts folder; where Opera on the Mac looks was not checked. On Windows the manifest path goes in the default value of the key `HKEY_CURRENT_USER\Software\Google\Chrome\NativeMessagingHosts\<host>`: in the real test of 2026-10-10, Opera GX 136 on a real Windows found and called the host registered only under that Chrome key. That says nothing about other Opera builds, and Opera's own help cites HKLM, not HKCU, so the evidence is the test, not the documentation. `ONDE_REGISTRAR_NO_WINDOWS` keeps Opera's entry so the destination can be adjusted if another test shows a different key.

The Windows `.bat` is what Chrome runs (through `cmd.exe`), and it only calls the system's own PowerShell by full path with the `.ps1` beside it, because the Native Messaging conversation has bytes that `cmd` cannot read. `-ExecutionPolicy Bypass` holds only for that process: the default Windows policy runs no `.ps1`, not even ours (a group policy of the machine still wins, and then the step says the opener did not answer). The `.bat` is ASCII only, since `cmd` reads it in the console's code page, so paths with accents live in the `.ps1`. The manifest of the host lets only the PerpetualMiner extension call it.
