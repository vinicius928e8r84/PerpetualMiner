# The e2e suite fakes the network at the HTTP boundary and blocks the rest

Each e2e test gets a new Chromium profile with the unpacked extension loaded from the root of the repository, the network faked at the HTTP boundary (the Conexão com o Anki, Gemini, Firestore and Google) and the fixture pages served by a local server. Any other external request is blocked, so no test goes out to the internet. Routes are registered so that the last one wins, and the general block comes first. A proxy of the environment (`HTTPS_PROXY`) would take the login window out of the local server, so it is cleared.

The Google login page is the exception of mechanism, not of rule: the window of `chrome.identity.launchWebAuthFlow` loads outside Playwright's routing, and `context.route` does not reach it, and neither does the ChatGPT login tab that `chrome.tabs.create` opens (it escapes on the first navigation). So the Chromium of the test points the names `accounts.google.com` and `auth.openai.com` to a local HTTPS server (`--host-resolver-rules`) with a self-signed certificate generated on the spot and accepted by `--ignore-certificate-errors`; only that server uses HTTPS. The real login runs without leaving the machine, and the test chooses what the window does. Any other path on that server, such as the `/ListAccounts` that Chromium asks for by itself, is a 404.
