# The engine runs inside Anki on the standard library only

The engine runs inside the Anki add-on, where there is no `openai`, `httpx`, `requests`, PyYAML or dotenv and the Python may be as old as 3.9. So it talks to OpenAI, to Openverse and to Google over plain `urllib`, reads `config.json` and the `.env` by hand, and writes progress to the `perpetualminer.motor` logger, never to stdout. The one thing that needs an imaging library, converting an image, goes through an adapter (`image_utils.usar_adaptador`): in the add-on it is the one made with Anki's Qt, everywhere else Pillow's, imported only when a conversion is asked for. Anki's Python on the Mac does not always find the system certificate authorities, but Anki ships `certifi`, so the HTTPS context uses it. The image calls (the judge, the screening, the generation) ask again twice after a passing refusal (408, 409, 429, 5xx, a timeout or no answer), as the SDK did; the text call does not, because the add-on waits and repeats it by itself.
