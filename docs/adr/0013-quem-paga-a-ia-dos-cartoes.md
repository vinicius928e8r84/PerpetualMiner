# The IA dos cartões is paid by the plan or by the key, and an Envio never moves from one to the other by itself

The text of each Cartão is paid in one of three ways, read before every request: the ChatGPT plan (the person signed in), the OpenAI key (no sign-in, or the person chose Usar a minha chave for that Envio), or stopped, with the reason (the sign-in ended, or the key is missing). One table, `complemento/ia_dos_cartoes.py`, decides who pays each step; it replaced the same decision scattered over six modules.

**The Envio never goes from the plan to the key on its own.** When the sign-in ends, the Envio stops with `chatgpt_signed_out`, and Tentar de novo stops it again, key stored or not. OpenAI's own guidance is that a request is not silently switched to another billing path, and spending the key without the person knowing would be worse. Only the person leaves the stopped state: sign in again, sign out, or Usar a minha chave, which also works with a sign-in that has ended. The plan hitting its usage limit does not stop the Envio: it waits for the plan, asks for the same text again every 5 minutes and resumes when the plan releases it.

**What the plan does not cover.** The plan covers the text, the correction of the Criação and the image judge. It never covers the voice or the generated image, which always use the key. When the plan refuses the image judge (usage limit, an account the plan does not serve, a sign-in refused or ended), the Cartão fails with the code, the paid text is kept and the Envio stops; otherwise the Cartão would go without a photo and no one would know, and Tentar de novo would have nothing to improve. A passing plan error is retried like one from the key, and if it persists the key's judge decides, or, without a key, the Cartão goes with no image.

**The model.** The Automático model is the first one the plan lists, or the engine's model with the key. An exit date for a model comes only from a list in our code that the owner fills in when OpenAI announces one (it ships with none, because OpenAI has announced none for these models); the plan's own list does not match its documentation, so it is not trusted for dates. Models used with the key are the ones the engine calls with `temperature`.

**Limits of the sign-in, accepted.** The `id_token` is checked only for its `nonce`, with no JWKS check, because the identity is neither used nor shown; the check enters when a screen shows the account. Renewing the sign-in and failing to save it (the Anki killed between the two) loses the new `refresh_token`, and the person signs in again. There is one sign-in per computer, and each sign-in registers a new client. A free or Go account is told apart by a second consecutive `invalid_grant`, since one refusal can be a spent code. The first 429 right after sign-in arrives as the usage limit, and the screen does not claim the quota ended.

**Not proven.** The real ChatGPT server, Windows, the quality of a Cartão made by the plan and its consumption on Plus or Pro, and an account at its limit. Those wait for the real-account proofs.
