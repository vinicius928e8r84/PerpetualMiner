# A test clock is built in one place, the relogioParado fixture

`page.clock.install` leaves the clock running, and a `pauseAt` with a margin invented by the test lands in the past when the next command is slow: in one test a 1.4 s timer ran before the assertion and, with 1,701 ms of delay, the pause one second ahead was refused with "Cannot fast-forward to the past". So the clock is built in a single owner, `e2e/relogio-parado.js`, behind the `relogioParado` fixture of `e2e/fixtures.js`, which prepares the instant and the pause together, before navigating, with a margin larger than the test's deadline; the rule `relogio-fora-da-fixture` flags `clock.install` and `clock.pauseAt` anywhere else in `e2e/`. We rejected raising the timeout or the retry of a test: it hides the race instead of removing it.
