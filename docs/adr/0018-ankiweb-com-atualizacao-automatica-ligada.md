# The Conexão updates itself from AnkiWeb, on by default, and only works from the file AnkiWeb serves

The Conexão com o Anki asks AnkiWeb for its own id when the Anki opens and every 6 hours, installs a newer version without asking, and turns off the Anki's own update flag for itself (`complemento/atualizacao.py`). `ATUALIZACAO_AUTOMATICA` is `True` by default since version 0.4.20.

**Why it is on.** The owner read the AnkiWeb terms (2026-11-09): nothing forbids an add-on that updates itself, the license is AGPL-3.0, and what the terms ban is third-party clients. Leaving it on by default does not go against them, and the flag goes back to `False` only for another reason. The Anki functions it uses (`fetch_update_info`, `get_updated_addons`, `download_and_install_addon`, `addon_meta`, `write_addon_meta`) were read in the source of Anki 26.09 and proven on a real Anki on the owner's Mac, where the swap from 0.4.20 to 0.4.21 happened with no dialog. `AnkiWebDoAnki.pronto()` checks that those functions exist before using them; if an Anki changes one, the Conexão does not query or install, undoes its flag, and the Anki's normal dialog comes back, never worse than that.

**The way out.** A person who does not want it creates the empty file `sem-atualizacao-automatica` in the Conexão's `user_files` (the Anki keeps that folder) and reopens the Anki: the Conexão starts with it off and the normal dialog returns. To turn it off for everyone, the owner changes the flag to `False` and uploads a new version. The Atualizar agora button of the extension, which is a click of the person, keeps working either way.

**It only works from the AnkiWeb file.** The id is the name of the Conexão's folder in the Anki (`addons21/<id>`), so a Conexão installed from a file that still has the old `package` (`perpetualminer`) has nowhere to update from. For the same family of reasons the `mod` in the `manifest.json` of the file that is uploaded must be the one AnkiWeb gives the page, never the upload time or the packaging time: with any other number, an Anki that installed by the file sees an "update" for the same version (a useless download on 25.09, and on 2.1.50 the Update Extensions dialog, which fails). That is the step after each upload, `python3 complemento/empacotar.py --mod-do-ankiweb conexao/perpetualminer.ankiaddon`, which the owner does by hand today and wants automated wherever it can be.

**Risks left open.** The Anki 2.1.50 floor was not tested on the owner's Mac. The support link of the AnkiWeb page must open without login before the page goes live. Whoever comes from a version before 0.4.20 still sees the Anki's dialog on that one update.
