# A verification run records the identity of its processes, not their pid

`/verify-perpetualminer` writes `drive.pid` with six values, one per line: the pid of `drive.sh`, its start time, its exact command line, the canonical path of the `drive.sh` that wrote it, the process group `drive.sh` gave the Playwright job, and that group leader's start time. A pid alone proves nothing, because pids are reused: `cleanup.sh` stops a process only when its start time and its command match the record, and stops a group only when the record was written by this checkout's `drive.sh` and the group still has members (a group id cannot be reused while any member lives; if the leader's pid is alive again with another start time, the recorded group is gone and the number belongs to something else). The job runs in its own process group so `cleanup.sh` can stop it even if `drive.sh` dies first, and the Playwright `--output` is outside `evidence/` because Playwright empties it at the start of every run. We chose a record that is more work to write over killing the wrong process of a machine the person is using.
