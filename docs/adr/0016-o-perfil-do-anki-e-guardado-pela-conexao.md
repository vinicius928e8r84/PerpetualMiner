# The Conexão keeps the Perfil do Anki; the extension does not

Cartões enter only the Perfil do Anki that was marked at the first connection (the first profile found open). The Conexão com o Anki is the only owner of that choice, in `perfil.json`, and the opener script that Native Messaging reads is written from it. The extension keeps no profile, which settles the case of two Chrome profiles on one computer: there is one owner. The reason for an owner outside the browser is that the state lives in more than one process and the Conexão now closes and opens profiles of the person's Anki.

**What the Conexão does.** It never deletes, renames or writes profiles or collections by itself. The note is written only into the marked profile, and the check of the profile and the write happen in the same step on the Anki's main thread, so no profile switch fits between them. If another profile is open the Envio waits ("O Anki está no perfil X. O Envio espera.", with Abrir <perfil>); if the marked profile no longer exists the Envio waits and the screen asks to choose again. A file that cannot be read is "a Conexão não respondeu" and nothing is marked over it. The person undoes any of this by choosing another profile. The check is made by the collection adapter on the main thread of the Anki, in the same step that writes: with another profile open it raises `OutroPerfil`, and with the marked one renamed or deleted, `PerfilSumiu`. The Conexão opens the marked profile only when the Anki is on the profiles screen; with a profile open the switch only comes from the click on "Abrir <perfil>", which closes the open profile the normal way (so it syncs) and opens the marked one.

**Traps the code does not confess.** With a modal dialog open (Excluir or Renomear in the profile manager) the Conexão must not enter a profile on its own, because the confirmed action would act on the profile it just loaded. A second click during the sync that runs when a profile closes must not close it again. The opener must not receive `-p` with a profile that does not exist (the Anki 2.1.50 does not open).

**Risks accepted.** The Conexão enters a profile on its own only when an Envio is waiting, so someone who opened the Anki just to study is not pulled into a profile, and at most once every 15 s; that interval is an estimate, not measured on a real Anki. Reads (Baralhos, numbers, Vocabulário) still come from whichever profile is open. The names of profiles in `state.waiting` enter the diagnostic package, like the Baralho name, and whether they should is still to be decided. The profile of the older configuration is not migrated.

**Not proven.** The Anki functions that handle profiles (`pm.load`, `onOpenProfile`, `unloadProfile`, the open Excluir/Renomear) ran only against a fake `mw`, read in the Anki 26.9.3 source. The proof on the real path is the owner's rehearsal on Mac and Windows, including the double click and the modal with a test profile.
