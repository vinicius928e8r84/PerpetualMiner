# The engine never sees a credential, or a place to send it

The engine that writes the cards runs inside the Anki add-on, and nothing in it holds a secret or chooses where a request goes. A stage asks through a `pedir` that its caller gives (or through a `PelaChave`, the key already bound to its provider, or a judge that comes ready), so who pays (the key or the ChatGPT plan) and the cost record are the caller's; the engine only asks with a model. The base URL of each provider (`openai_base`, `openverse_base`, `base` of a credential) is passed by code, never read from `config.json`, the environment or the request: the file's keys are dropped, so nothing outside the code can redirect the key. A refusal becomes a code (`ErroDoProvedor`, `ErroDaOpenAI`), never what the provider wrote, because the message of a rejected key repeats parts of it, and an error that is not the provider's is logged by its type alone for the same reason. What the person mined is not written outside the Envio's own files: the log, the file names and the cost records name a card by its id (`<phraseId>-<n>`), never by its keyword or phrase, and a log of an unusable card says only its size.
