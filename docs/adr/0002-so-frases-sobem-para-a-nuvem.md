# Only Frases go to the Nuvem, through the Firestore REST API, with no retry queue

The extension syncs the Histórico to Firestore under `usuarios/{uid}/frases/{id}` by calling the Firestore REST API directly, and signs in with `chrome.identity.launchWebAuthFlow` (Google OAuth). There is no Firebase SDK, neither for data nor for auth: a Manifest V3 extension page cannot load remote or SDK code under its CSP. There is no retry queue either: a capture is saved locally first, a failed upload leaves no record, and the next `carregar` in `lib/sincronizacao.js` uploads the local Frases the Nuvem lacks. A queue would be a second copy of state to keep right, and the reload already covers it. Reading `meta/deleted` is the same kind of choice: a `404` means "no deletions yet", and any other failure makes `carregar` reject before it uploads or removes anything, so a failed read never turns into a wrong delete; the next opening retries.

Only `frases` crosses to the Nuvem. Every other key in `chrome.storage.local` belongs to the computer it is in, on purpose: the theme, the four-decimal cost display, the ids of the Envios. Two names look wrong and stay. A Frase already sent keeps `status: 'exported'` (older than the glossary term Enviada ao Anki) because that value is written on every computer and in Firestore, so renaming it needs a migration of both. The theme (`pm_tema`) is mirrored in `localStorage` before first paint so the page does not flash the wrong theme; `chrome.storage` stays the source and corrects the mirror.

We rejected the Firebase SDK (blocked by the CSP) and a retry queue (more state, no gain over `carregar`). We rejected syncing the other keys because they describe one computer: a second computer with a different Anki, theme or cost view must not inherit them.
