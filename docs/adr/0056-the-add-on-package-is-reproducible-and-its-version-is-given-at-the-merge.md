# The add-on package is reproducible, and its version is given at the merge

`complemento/empacotar.py` builds the `.ankiaddon` with the date, permissions and order of every zip entry fixed (the smallest date the zip accepts, Unix as the system). The `mod`, the time the code changed, puts the installed copy on AnkiWeb's update path and only rises when the code does: if the code is the one of the versioned `conexao/perpetualminer.ankiaddon`, the `mod` is that file's, so running twice gives the same bytes; if it changed, it is the current time or `SOURCE_DATE_EPOCH`. After the upload AnkiWeb gives the page its own time (the `t=` of the download redirect), which is never the time the file was made, so `--mod-do-ankiweb` writes the file AnkiWeb serves with only the `manifest.json` changed, and the Anki that installs from it is already at AnkiWeb's version and does not offer the same update again.

A PR does not touch `VERSAO`, `versoes.json` or the `.ankiaddon` (the rule `versoes-publicadas` bars it): the version is given after each merge by `complemento/versao_no_merge.py`, in one commit. The tests that demand the package and its hash hold on `main` and on that commit, not on the push to `main` before it, where the file is behind the code by design. The packaging itself refuses to run unless HEAD is a green commit, tagged by the full suite on `main`.
